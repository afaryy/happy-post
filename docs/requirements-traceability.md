# Requirements Traceability

| Requirement | Baseline decision | Evidence location |
| --- | --- | --- |
| Frontend and backend application delivery | Next.js frontend and FastAPI backend are separate services; both MVPs are implemented locally | [Architecture](architecture.md), [Backend MVP](../backend/README.md), [Frontend MVP](../frontend/README.md) |
| Health and version endpoints | Backend has `/healthz` and `/version`; frontend has container-local `/healthz` and `/version` plus public `/frontend/*` aliases | [Backend MVP](../backend/README.md), [Frontend MVP](../frontend/README.md), [`frontend/app/healthz/route.ts`](../frontend/app/healthz/route.ts), [`frontend/app/version/route.ts`](../frontend/app/version/route.ts) |
| Containerisation | Separate non-root FastAPI and Next.js images are implemented; Compose defines local PostgreSQL, migration, backend, and frontend services with loopback host bindings, health checks, and internal `backend:8000` / `db:5432` routing | [`backend/Dockerfile`](../backend/Dockerfile), [`frontend/Dockerfile`](../frontend/Dockerfile), [`compose.yaml`](../compose.yaml), [Local containers validation](local-containers-validation.md) |
| Automated tests and checks | Backend/frontend CI, Terraform validation, scanner gates, immutable image publication, and controlled ECS delivery controls are implemented | [Backend MVP](../backend/README.md), [Frontend MVP](../frontend/README.md), [CI/CD](cicd.md), [Implementation backlog](implementation-backlog.md) |
| Image scanning and registry | The applied platform root defines one private immutable, scan-on-push ECR repository per workload; automatic and main-only manual publication block HIGH/CRITICAL image findings and record verified SHA-256 digest/source-commit artifacts | [Architecture](architecture.md), [Security decisions](security-decisions.md) |
| ECS delivery | Two digest-pinned Fargate services are active behind the applied ALB. Initial bootstrap is Terraform-only; controlled component-selected deployment has successfully updated both services, verified public HTTPS smoke tests, and supports known-good rollback | [Architecture](architecture.md), [Deployment and rollback](deployment-and-rollback.md), [Operations](operations.md) |
| Public domain and TLS | Cloudflare delegates the application subdomain to Route 53; the applied edge root validates ACM DNS and terminates HTTPS at ALB | [Architecture](architecture.md) |
| Persistent application data | The P6 application stores flexible, user-scoped happy-item daily entries through the backend `DATABASE_URL`; deployed private RDS PostgreSQL is reachable only from the backend service | [Architecture](architecture.md), [Security decisions](security-decisions.md), [Backend MVP](../backend/README.md) |
| Database migration control | Database-changing backend releases use a manual `main`/`sandbox` workflow that verifies the backend image digest and source commit before running `alembic upgrade head` as a one-off private ECS task | [Deployment and rollback](deployment-and-rollback.md), [Operations](operations.md) |
| User data separation | MVP email/password sign-up and sign-in scope entries to the authenticated user; production identity is deferred to a managed provider before real users | [Security decisions](security-decisions.md), [Backend MVP](../backend/README.md), [Frontend MVP](../frontend/README.md) |
| Database recovery | RDS automated backups and point-in-time recovery are configured for one day in sandbox, the active Free Plan maximum replacing the seven-day target; a future paid environment restores the longer objective | [Operations](operations.md) |
| Infrastructure as code | Terraform manages foundation and steady-state resources after bootstrap | [Architecture](architecture.md) |
| Controlled deployment | One GitHub environment, `sandbox`, provides deployment role and configuration separation without required reviewers; deployment branches are restricted to `main` | [Security decisions](security-decisions.md), [Deployment and rollback](deployment-and-rollback.md) |
| Rollback | Immutable image digests and ECS revision rollback are required; the rollback workflow is available and should be rehearsed only if time permits before assessment submission | [Deployment and rollback](deployment-and-rollback.md), [Operations](operations.md) |
| Least privilege | OIDC trust, separate operational roles, and narrow runtime permissions | [Security decisions](security-decisions.md) |
| End-to-end TLS | Deferred optional enhancement, not baseline | [Architecture](architecture.md) |

This table records the approved design, completed application MVPs, local containerisation, applied Terraform network, RDS data, platform, edge, service roots, CI controls, and successful controlled ECS deployment smoke tests. The P6 workload implementation adds database-backed user accounts, opaque sessions, and daily entries; deploying it requires running the controlled migration workflow through `0002_create_users_daily_entries` before the backend image that depends on it.
